# 因子如何发现、判断与监控

增长工作台中的「因子」是一个需要持续核验的商业假设，例如「某品牌的促销公告可能与收纳用品订单增长有关」。系统从订单变化中自动提出候选，展示可用的站内信号与外部线索；使用者核对证据后，才能将其登记为监控规则。候选、规则、发现的事件是三个不同对象，不能把发现一条公告直接解释为订单变化的原因。

## 从订单数据发现候选

1. 在「数据中心」导入订单文件，在「增长工作台 → 订单与诊断」检查字段映射、金额单位和实际覆盖区间。订单按支付日期计入，退款从该订单的净 GMV 中抵减，未支付和取消的订单不计入支付指标。历史文件与当期文件应分别声明真实覆盖时间。
2. 在「时间窗口分析」选择起止日期、异常变化阈值和最低订单数。默认阈值为 `0.3`（同比变化绝对值达到 30%），最低订单数为 `5`。系统按北京时间日历日期取去年同期，分别统计品牌或市场、品类或客群、商品三个维度的订单量和净 GMV。
3. 只有本期与去年同期的订单覆盖都完整，系统才计算同比。对每个分组，当前或去年同期订单量至少达到最低订单数，并且订单量或净 GMV 至少一项的同比变化绝对值达到阈值，才生成异常与待核验候选。同比为 `(本期值－去年同期值) ÷ 去年同期值`。某项指标的去年同期值为零时，该项同比标为未知；另一项指标若满足条件，仍可触发候选。

这些条件用于挑出值得调查的变化，不表示已经找到原因。覆盖不完整时不会用缺失记录推断「零需求」，也不会按不完整数据生成同比异常。最低订单数只排除部分小样本，不能替代统计显著性检验。

## 候选带有什么依据

每个候选保存触发它的分组、两期订单量与净 GMV、同比和覆盖状态。若接入了站内行为，报告还展示私信、评论、点赞、收藏的聚合计数，并在品牌或市场、品类或客群层面关联当前与去年同期的信号量；只有两期信号覆盖完整且去年同期数量非零，才显示信号同比。商品级候选目前没有商品级站内信号关联。

配置 Brave Search 后，系统会针对报告中最多五个相关品牌或市场补充外部搜索线索，每个检索最多保留五条标题、摘要、网址和检索时间。这些结果标记为「未核验」：它们只是供打开原始来源检查的线索，不会自动匹配成某个候选的证据，也不会自动确认来源真实性或因果关系。未配置搜索服务时，订单与站内信号分析仍可使用。

候选会显示待核验假设、原始依据和下一步核对建议，因果状态始终是「尚未确认」。每次重新分析会产生新的报告和候选 ID；这不代表出现了新的商业原因。

## 怎样判断因子是否合理

打开候选的依据后，建议按下面的顺序核对，再决定是否转为监控规则：

| 要核对的内容 | 具体判断方式 | 不满足时 |
|---|---|---|
| 数据口径 | 确认两期订单覆盖完整，支付状态、金额单位、退款处理和分组名称一致 | 先修正导入或覆盖区间，重新分析 |
| 变化幅度与样本 | 查看触发阈值的是订单量还是净 GMV；核对两期绝对值，避免只看百分比 | 将候选留作线索，不据此确定原因 |
| 时间顺序 | 核对公告发布时间、活动起止时间和订单变化区间；「首次发现时间」只是系统看到链接的时间 | 日期不明时继续求证，不把抓取时间当发布日期 |
| 对象范围 | 核对公告对应的品牌、品类、商品与分析分组是否一致 | 不一致时不转为该分组的监控规则 |
| 其他解释 | 对照价格、库存、渠道、活动和站内行为覆盖变化 | 存在更直接解释时，调整假设并继续观察 |
| 来源可靠性 | 打开原始公告，确认它确属该品牌或活动的官方站点，并检查正文 | 仅有搜索摘要或转载时暂不批准事件 |

例如，某品牌收纳用品去年同期有 50 笔、本期有 80 笔已支付订单，订单量同比为 60%；两期覆盖完整，且阈值为 30%、最低订单数为 5，系统会生成候选。假如同期收藏量也增加，系统会把它列为相关线索。如果又检索到一条促销公告，使用者仍需打开官网，核对公告日期、适用商品、活动渠道和价格变化。公告发生在订单上涨之后、只针对其他商品，或来源只是转载，都不足以把「促销驱动增长」作为已确认结论。

目前系统的自动判断停留在覆盖检查、阈值初筛和线索整理。它没有给候选计算合理性评分、进行统计显著性检验、跨来源自动交叉验证、识别因果关系，或自动淘汰不合理候选。Agent 的「因子研究」可以根据获准读取的数据给出文字分析建议，但不会代替审核，也不会创建或批准监控规则。

## 从候选到持续监控

认为某个候选值得继续跟踪时，在报告中将其转为监控规则，或在「事件与因子」手动新建。填写清晰的因子名称、品牌或市场、检索词、公告标题关键词和官方域名白名单；可以填写最多十个 HTTPS 公告列表页。域名白名单由使用者核实后填写。规则创建后处于「待审核」，使用者检查来源与范围，再选择「批准并启用监控」或「拒绝」。只有已批准的规则会运行。

监控时，配置了公告列表页就读取页面中的公告链接；否则通过 Brave 在白名单域名范围内搜索。系统过滤没有匹配标题关键词、来源域名不合规和通用导航标题的结果，按品牌或市场与 URL 对事件去重。新事件仍为「待审核」，不会因标题匹配而自动成为可信证据。规则检查失败会记录错误并退避重试；在「接入设置」启用后台调度后，才会按间隔持续检查，也可以在页面手动立即检查。

核对新事件的原始来源、发布日期、适用对象和潜在人群规模后，使用者可以批准或拒绝事件。只有已批准的事件才能进入机会方案；即使开启 `auto_propose`，生成的方案仍是待审批状态。事件审核、方案审批与投放执行是连续的独立步骤。完整配置与接口见 [增长工作台](GROWTH.md)，模型分析的读取权限见 [Agent 工作台](AGENTS.md)。
